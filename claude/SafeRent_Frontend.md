# SafeRent — Клиентская часть (Frontend). Техническая документация

> Документ для дипломной работы. Описывает реализованную клиентскую часть
> (одностраничное веб-приложение) платформы аренды жилья **SafeRent**:
> технологии, структуру, экраны, ключевые компоненты и логику, взаимодействие с
> API, а также раздел «Что замокано / что предстоит реализовать».

---

## 1. Назначение

Клиентская часть SafeRent — это **SPA (Single Page Application)** на React,
которое предоставляет интерфейс для трёх ролей:

- **Арендатор (TENANT)** — поиск и бронирование квартир, договоры, оплата, чат,
  осмотр, избранное, отзывы;
- **Арендодатель (LANDLORD)** — публикация и управление объявлениями, заявки,
  договоры, чат;
- **Администратор (ADMIN)** — модерация объявлений и жалоб, управление
  пользователями.

Приложение общается с серверной частью (см. `SafeRent_Backend.md`) исключительно
по REST API через axios.

## 2. Технологический стек

| Технология | Версия | Роль |
|------------|--------|------|
| React | 19 | UI-библиотека, компонентный подход |
| TypeScript | ~6.0 | Статическая типизация |
| Vite | 8 | Сборщик и dev-сервер (быстрый HMR) |
| React Router | 7 | Клиентская маршрутизация |
| Zustand | 5 | Глобальное состояние (хранилище пользователя) |
| axios | 1.16 | HTTP-клиент к REST API |
| Tailwind CSS | 3.4 | Utility-first стилизация |
| lucide-react | — | Набор иконок |
| react-hot-toast | 2.6 | Всплывающие уведомления (toast) |

### Почему так

- **React + TypeScript** — типобезопасный компонентный UI; типы (`types/index.ts`)
  повторяют контракты API, что ловит ошибки на этапе компиляции.
- **Vite** — мгновенная пересборка при разработке.
- **Zustand** вместо Redux — минималистичное хранилище без boilerplate; в нём
  держится сессия пользователя (токен, роль, флаги `verified`/`admin`) с
  сохранением в `localStorage`.
- **Tailwind** — быстрая консистентная вёрстка без отдельных CSS-файлов.

```

├── api/            ← обёртки над REST-эндпоинтами (по одному файлу на домен)
│   ├── axios.ts        — настроенный экземпляр axios (интерцепторы)
│   ├── auth.ts, apartments.ts, bookings.ts, contracts.ts,
│   ├── payments.ts, inspections.ts, chat.ts, notifications.ts,
│   ├── favorites.ts, reviews.ts, reports.ts, districts.ts,
│   ├── landlords.ts, users.ts, admin.ts
├── components/
│   ├── apartment/  — ApartmentCard, PhotoCarousel
│   ├── common/     — Modal, LoadingSpinner, ProtectedRoute, StatusTag, EmptyState, Logo, ProtectionBlock
│   └── layout/     — Layout, Navbar, BottomNav
├── pages/          ← экраны приложения (по доменам)
│   ├── auth/       — RegisterPage (вход + регистрация + OTP)
│   ├── home/       — HomePage (листинг + поиск)
│   ├── apartment/  — ApartmentDetailPage, CreateApartmentPage
│   ├── booking/, contract/, payment/, inspection/
│   ├── chat/, notifications/, favorites/, map/, profile/
│   └── admin/      — AdminPage (модерация)
├── store/          — userStore.ts (Zustand)
├── types/          — index.ts (TypeScript-интерфейсы доменной модели)
├── utils/          — format.ts (формат валюты KZT, дат)
├── App.tsx         — маршруты
└── main.tsx        — точка входа
```

Принцип организации: **слой API** (`api/*`) отделён от **слоя экранов**
(`pages/*`). Экраны не вызывают axios напрямую — они импортируют функции из
`api/*`, что упрощает поддержку и переиспользование.

---

## 4. Слой доступа к API

**Файл `api/axios.ts`** — единая точка конфигурации:

- базовый `baseURL` API;
- **интерцептор запроса**: подставляет JWT в заголовок `Authorization: Bearer
  ...`; если тело запроса — `FormData` (загрузка файлов), **удаляет** заголовок
  `Content-Type`, чтобы браузер сам выставил `multipart/form-data` с корректным
  boundary (это была решённая проблема с загрузкой фото);
- **интерцептор ответа**: при `401 Unauthorized` очищает сессию и перенаправляет
  на `/login`;
- `apiErrorMessage(err)` — единый помощник для извлечения текста ошибки из ответа
  сервера (используется во всех `toast.error`).

Остальные файлы `api/*.ts` — это тонкие функции-обёртки (`getById`, `create`,
`verify`, `getUsers`, `setAdmin` и т. д.), возвращающие типизированные данные.

---

## 5. Маршрутизация и защита доступа

**Файл `App.tsx`** определяет маршруты:

- Публичные: `/register`, `/login` (оба используют `RegisterPage`).
- Защищённые (внутри `<ProtectedRoute>` + общий `<Layout>`):
  `/` (листинг), `/apartments/:id`, `/create-apartment`, `/bookings`,
  `/contracts`, `/contracts/:id`, `/payment/:contractId`,
  `/inspection/:contractId`, `/chats`, `/chats/:chatId`, `/notifications`,
  `/favorites`, `/map`, `/profile`, `/admin`.

**`ProtectedRoute`** проверяет наличие сессии и при её отсутствии отправляет на
вход. **`AdminPage`** дополнительно проверяет флаг `admin`: если он не выставлен,
делает `<Navigate to="/" replace />` — обычный пользователь не попадёт в панель
модерации, даже зная URL.

---

## 6. Глобальное состояние (Zustand)

**Файл `store/userStore.ts`** хранит сессию: `userId`, `userName`, `role`,
`verified`, `admin`, `avatarUrl`, токен. Данные сохраняются в `localStorage`,
поэтому сессия переживает перезагрузку страницы. Метод `logout()` очищает
хранилище; после выхода навигация ведёт на `/login`.

## 7. Ключевые экраны и компоненты

### 7.1 Аутентификация — `RegisterPage`
Единый экран входа/регистрации с шагом подтверждения OTP-кодом из письма (в
dev-режиме код виден в MailHog на `:8025`). После успешного входа в `userStore`
кладётся сессия, включая флаги `verified` и `admin`.

### 7.2 Листинг и поиск — `HomePage`
Сетка карточек `ApartmentCard`. Показываются **только верифицированные** активные
объявления (фильтрация на сервере). Полнотекстовый поиск с устойчивостью к
опечаткам (fuzzy) обращается к Elasticsearch через `apartments.search`.

### 7.3 Карточка и карусель фото — `ApartmentCard`, `PhotoCarousel`
**`PhotoCarousel`** — переиспользуемый компонент:
- стрелки «влево/вправо» для листания (скрываются, если фото одно);
- индикатор-точки;
- **лайтбокс**: по клику по центру фото открывается во весь экран с навигацией с
  клавиатуры (`Esc`, стрелки);
- плейсхолдер-заглушка, если фото нет.

### 7.4 Детальная страница — `ApartmentDetailPage`
Карусель фото, цена (формат KZT), площадь/комнаты/дата заселения, блок защиты
сделки (`ProtectionBlock`), бейджи «Verified»/статус. Действия зависят от роли:
- арендатор — «Сообщение» (открыть чат), «Book Now» (бронь, **только если
  квартира верифицирована и аккаунт подтверждён**), «В избранное», «Пожаловаться»
  (`ReportModal` с выбором причины);
- владелец — «Редактировать», бейдж «На модерации»; если объявление отклонено —
  блок с **причиной отклонения** (`rejectionReason`);
- админ — кнопка быстрой верификации.

### 7.5 Создание объявления — `CreateApartmentPage`
Форма создания/редактирования. Фото загружаются как `ApartmentPhoto[]` с
возможностью удаления каждого (для уже сохранённых вызывается реальное удаление на
сервере, для ещё не отправленных — удаление в UI). Загрузка идёт через MinIO.

### 7.6 Бронирование и договоры — `BookingsPage`, `ContractsPage`, `ContractDetailPage`
Просмотр заявок (для арендатора — свои, для арендодателя — входящие),
подтверждение/отклонение, переход к договору, его подписание обеими сторонами.

### 7.7 Оплата — `PaymentPage`
Оплата залога и аренды по договору; отображается статус эскроу. Способы оплаты:
Kaspi / Halyk / карта (см. раздел «Замокано»).

### 7.8 Осмотр — `InspectionPage`
Загрузка фото check-in и check-out по комнатам, запуск ИИ-сравнения, отображение
результата (средний SSIM, решение по залогу). Реализованы **удаление отдельного
фото** (×) и кнопка **«Очистить»** (сброс всех фото осмотра).

### 7.9 Чат и уведомления — `ChatListPage`, `ChatDetailPage`, `NotificationsPage`
Диалоги с арендодателем/арендатором, счётчики непрочитанного в `Navbar`
(обновляются каждые 30 секунд), лента уведомлений.

### 7.10 Профиль, избранное, карта — `ProfilePage`, `FavoritesPage`, `MapPage`
Профиль с аватаром (загрузка в MinIO), список объявлений арендодателя; избранное
арендатора; карта районов.

### 7.11 Админ-панель — `AdminPage`
Три вкладки:
- **PENDING** — очередь объявлений на модерацию; кнопки «Verify» и «Reject».
  `RejectModal` позволяет выбрать причину из списка (`REJECTION_REASONS`) и
  добавить комментарий.
- **REPORTS** — жалобы пользователей; `ResolveReportModal` для закрытия жалобы с
  резолюцией.
- **USERS** — таблица всех пользователей с поиском и переключателем прав
  администратора (переключатель для самого себя заблокирован).

### 7.12 Навигация — `Navbar`, `BottomNav`, `Layout`
Навбар формирует пункты меню в зависимости от роли (`tenantItems` /
`landlordItems`) и добавляет пункт **Admin** (иконка щита) при `admin = true`.
Бейджи непрочитанных чатов и уведомлений. Кнопка выхода ведёт на `/login`.

## 9. Типизация доменной модели

**Файл `types/index.ts`** содержит TypeScript-интерфейсы, зеркалящие ответы API:
`User`, `AuthResponse`, `Apartment`, `ApartmentPhoto`, `Booking`, `Contract`,
`Payment`, `EscrowStatus`, `Chat`, `Message`, `Notification`, `InspectionPhoto`,
`InspectionCompareResult`, `Favorite`, `Review`, `UserRating`, `Report`,
`District`, `LandlordProfile`, обобщённый `Page<T>` и строковые union-типы
статусов (например, `ApartmentStatus`, `PaymentMethod`, `ReportReason`). За счёт
этого вызовы API и пропсы компонентов проверяются компилятором.

## 10. Замоканные (имитированные) функциональности

1. **Оплата.** Реального платёжного шлюза нет: экран оплаты показывает выбор
   способа (Kaspi / Halyk / карта), но списание имитируется — сервер сразу
   помечает платёж как успешный. Формы карты (номер/CVV/срок) и QR — это
   интерфейсная имитация.
2. **OTP-код.** В режиме разработки приходит не на реальную почту, а в MailHog
   (UI на `:8025`).
3. **Карта районов (`MapPage`).** Данные о безопасности/комфорте районов —
   демонстрационные (приходят из сидера сервера).
4. **ИИ-результат при сбое загрузки фото** трактуется как «повреждений нет»
   (значение по умолчанию приходит с сервера).

## 11. Что предстоит реализовать (Roadmap клиента)

1. **Переключатель языка (i18n)** — интерфейс на казахском, русском и английском.
2. **История ИИ-анализов** — экран с парами фото «до/после», кнопкой «посмотреть
   изображение» и возможностью обжаловать решение по залогу.
3. **Кошелёк в личном кабинете** — баланс, пополнение, возврат залога, история
   транзакций и действий.
4. **Дашборд доходов арендодателя** — поступления от аренды, бонусы, компенсации.
5. **Досрочное расторжение договора** — соответствующий UI-процесс.
6. **Реальные платёжные экраны** — рабочий QR Kaspi/Halyk и карточная форма с
   эквайрингом вместо имитации.
7. **ИИ-ассистент в чате** — подбор квартир с аргументами «за/против», ответы по
   договору, статистика для арендодателя.

## 12. Запуск (для воспроизведения при защите)

1. Поднять инфраструктуру: `docker compose -f docker-compose.dev.yml up -d`
   (PostgreSQL, MinIO, Elasticsearch, MailHog, AI-сервис).
2. Запустить серверную часть (Spring Boot) — наполнит БД тестовыми данными и
   проиндексирует объявления.
3. Запустить клиент: `npm install && npm run dev` (Vite поднимет dev-сервер на
   `http://localhost:5173`).
4. Тестовые входы (пароль `password123`):
   `admin +77000000000`, `landlord +77011111111`, `tenant +77044444444`.
